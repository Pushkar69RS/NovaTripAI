# Decisions

- 2026-08-27 — Form-first intake: a structured form collects trip constraints before any chat.
- 2026-08-27 — Planner is deterministic (cluster + 2-opt + validator); the LLM only parses chat edits and narrates.
- 2026-08-27 — Supabase Postgres + pgvector is the single store (relational data and vectors).
- 2026-08-27 — Hybrid retrieval (full-text + vector) fused with Reciprocal Rank Fusion (RRF).
- 2026-08-27 — Embeddings computed locally with intfloat/multilingual-e5-small; no embedding API.
- 2026-08-27 — Demo runs on localhost for the review; Vercel deployment comes post-review.
- 2026-08-27 — No orchestration framework (LangChain, LlamaIndex, etc.) in v1.
- 2026-08-27 — poi.city is the hub city (Mysuru, Hampi, Bengaluru, Chikmagalur, Coorg) used for clustering and intercity legs; the locality (Srirangapatna, Belur, Halebidu, Kushalnagar...) lives in the name and tags.
- 2026-08-27 — Extensions live in the `extensions` schema (Supabase convention); the migration references `extensions.vector` explicitly so nothing depends on search_path.
- 2026-08-27 — seed.py is a full reload (TRUNCATE ... RESTART IDENTITY of poi, poi_edge, intercity_leg, advisory). doc_chunk is included only while it is empty (Postgres requires it because of the FK); once it has rows the seed aborts and asks.
- 2026-08-27 — Web verification (Tavily) covers only the top-20 Mysuru/Hampi POIs; a verified row cites exactly one source_url and the report lists disagreeing sources. Everything else stays trust=draft and is labelled estimated.
- 2026-08-27 — The planner is offline-testable by construction: `build()` takes every input in memory and `plan()` is the only function that touches the database. The tests drive `build()` from data/pois.json, so the whole planning path runs with no connection.
- 2026-08-27 — One hard stop per day: the day's highest-scoring POI is the anchor, everything else is soft. Repair never drops or moves an anchor. A `booking_required` column would be the better signal once bookings exist.
- 2026-08-27 — Every in-city hop is timed at the one city speed. Hops under 1 km are labelled walks so a day can report walk_km against road_km, but a separate pedestrian speed would make travel minutes non-monotone in kilometres, and 2-opt minimises minutes while the map toggle compares kilometres — the two have to agree or route_km_before can come out below route_km_after.
- 2026-08-27 — TRAVEL_OVERRUN counts only a day's own hops, not the transfer into the city, and names the stop whose hops cost the most. Counting the transfer made arrival days unfixable, and dropping the lowest-scoring stop instead of the outlier made the ratio worse with every repair.
- 2026-08-27 — NO_MEAL_GAP reads as "more than five hours over midday with no food stop". The candidate shortlist reserves one midday-open food POI per day, so the repair loop never answers a meal gap by deleting sights.
- 2026-08-27 — Repair picks the least-repaired day first. Taking violations in day order let one stubborn early day spend the whole 8-iteration budget and leave a later day badly broken.
- 2026-08-27 — Every city gets at least one day in the allotment, even when there are more cities than days; the feasibility gate is what turns that over-subscription into Verdict(impossible) with the arithmetic, rather than a city silently getting zero days.
- 2026-08-27 — `PlanMetrics.improvement_pct` stays a percentage: the no-percentages rule governs itinerary and verdict content (comfort is the words comfortable|tight), while metrics is engineering telemetry for the review.
- 2026-08-28 — e5 prefixes live in one place. `app/rag/embed.py` is the only module that knows a document is "passage: ..." and a query is "query: ...". Getting that wrong costs retrieval quality silently, so no caller is trusted to remember it.
- 2026-08-28 — The model is loaded once on first use rather than at import. Importing the retrieval layer should not drag torch into a process that only wants the SQL; `lru_cache(maxsize=1)` gives the once-per-process guarantee without the import cost.
- 2026-08-28 — The dense side indexes title + body + the POI name in English and Kannada + the city. A paragraph rarely repeats the full official name of what it describes, and short Kannada queries had nothing else to hold on to: before the anchors, "ಹಂಪಿ ಕಲ್ಲಿನ ರಥ" retrieved a Hampi chunk about market streets.
- 2026-08-28 — body_tsv indexes the POI name but NOT the city. The city is a location signal, and in a bag of words it makes all 74 Mysuru chunks match "Mysuru" at the same rank, which is noise. Location is what `Filters.city` is for. Measured: adding the city to the tsvector took hybrid Recall@5 from 0.933 to 0.900.
- 2026-08-28 — websearch_to_tsquery ANDs every term, which is right for a search box and wrong for a question. The strict query runs first; if it finds nothing the same parsed lexemes are re-run joined with OR. Without the fallback lexical Recall@5 was 0.067.
- 2026-08-28 — The loose lexical fallback does not get an RRF vote and does not satisfy the refusal gate. Its rank one carries the same weight as a confident dense rank one, and one common word in common is not evidence the corpus can answer anything. Letting it vote cost 0.033 Recall@5; letting it satisfy the gate dropped refusals from 6/6 to 1/6.
- 2026-08-28 — `search()` and `scripts/eval_retrieval.py` both rank through `retrieve.rank()`. The eval briefly measured raw fusion while the application used something else, and the table said nothing useful until they were the same code.
- 2026-08-28 — Eval questions name their expected chunks by title, not by id. Ids are assigned by the database and would go stale on any reseed; titles are unique across the corpus and are checked before the run starts.
- 2026-08-28 — The eval reports two blocks rather than one mixed set: 30 written questions and 10 name/keyword lookups. Well-formed questions are the half dense is best at and bare names are the half lexical is best at, and mixing them lets the ratio decide the headline. Nothing was removed from the thirty to make room for the ten.
- 2026-08-28 — Recorded honestly: hybrid does not beat both single methods on this corpus. It ties the better one in each regime at about twice the latency. Dense alone dominates lexical everywhere here. Hybrid stays for exact-name queries and as insurance for terms the embedder has not seen, and the eval says so rather than being tuned until it wins.
- 2026-08-28 — seed_chunks.py upserts on (city, title) and never deletes. Migration 002 adds that key so a re-run needs no TRUNCATE, which CLAUDE.md rule 4 would require asking about first.
- 2026-08-28 — data/chunks_curated.json is authoritative. It is loaded first, never rewritten (only source_url was attached, per its own note), and 56 generated drafts that overlapped a curated paragraph for the same place were dropped rather than kept as near-duplicates. Its localities (Srirangapatna, Belur, Halebidu) and short names (Chamundi Hill, Vittala Temple) are mapped to the poi table on load, so the file keeps Rohan's words and the database keeps its keys.
- 2026-08-28 — Superseded doc_chunk rows are `retired`, not deleted. Retrieval ignores them, the data stays, and the flag flips back with one UPDATE. Deleting is a rule-4 decision and stays Rohan's.
- 2026-08-28 — The Katha builder takes retrieval and the catalogue as arguments. The twenty-Katha rhythm test runs the real builder over the corpus files in memory with a word-overlap retriever, which is crude on purpose: the rules have to hold whatever retrieval hands back.
- 2026-08-28 — A city or day Katha opens on a city-level paragraph (the "opening" spine item), because the first segment must be a hook or story and the first stop's best paragraph is usually a fact.
- 2026-08-28 — A thin place borrows only city-level paragraphs (poi_id null) and the segment is labelled as the city. Filing a wrestling story under the zoo was the alternative, and it read as a lie.
- 2026-08-28 — Shares round to about one paragraph, so a 5-minute Katha came out at 3.5 minutes. `arrange()` now fills to 85% of budget in a second pass, most popular item first, still under the rhythm rules.
- 2026-08-28 — The narrator's post-check treats a completion cut off by the token cap as a failure. Kannada spends three to four tokens a word; DeepSeek's first bake-off run stopped mid-sentence at 900 tokens and nothing else would have noticed. Cap raised to 2000.
- 2026-08-28 — The bake-off chose nothing. `narrate_katha` stays on deepseek/deepseek-chat, the one model check_env verifies, until Rohan reads the three Kannada samples and writes the pick into app/llm/models.py. Candidates were checked against the live OpenRouter /models list, not memory.
- 2026-08-28 — Sarvam's REST shape was taken from docs.sarvam.ai on the day (api-subscription-key header; text, language_code, speaker, model, pace, speech_sample_rate, output_audio_codec; base64 `audios[]`), not from memory. speak() never raises; None means "use the browser's voice".
- 2026-08-28 — A chat message with no edit verb is a Question and never calls the model for classification. Edits are parsed to strict JSON and validated; anything off-shape or unresolvable asks one question. Cheaper, deterministic in tests, and a guess is worse than a question.
- 2026-08-28 — An edit rebuilds one day through `rebuild_day()`; the other Day objects are reused, so they are byte-identical by construction and the test asserts it on the serialised days. `build_day` gained a `day_start` (not `start`, which it already used for the nearest-stop index — the collision cost a test run).
- 2026-08-28 — The retrieval eval fell from 0.933 to 0.867 Recall@5 after the merge and the table says so. Three curated answers phrase things differently from the questions, and one Kannada query lost its chunk. Not tuned back.
- 2026-08-28 — The frontend is server pages (Jinja2) and one vanilla JS file over the JSON API: no framework, no build step. Templates format; every number is computed by the modules the API already uses and handed to the page as JSON.
- 2026-08-28 — Fonts are self-hosted (woff2 in app/static/fonts, latin/latin-ext/Kannada subsets, variable files where Google serves them). A page load makes no external request, so the browser side of the demo survives dead WiFi; the database does not, and the plan does not pretend otherwise.
- 2026-08-28 — The map's honest baseline is "as listed": the day's stops in candidate-score order, which is what an itinerary that never routes visits. Nearest-next was already 2-opt-optimal on the demo trip (30.9 km before and after), so before/after said nothing; listed against routed (34.98 vs 30.9 km, Day 2 10.53 vs 6.45) says it.
- 2026-08-28 — Day.route_km is measured exactly like Day.naive_km (matrices + total, two decimals). Adding up the rounded hop kilometres gave 6.4 against 6.37 on Day 1 and read as "the list was shorter".
- 2026-08-28 — All three scoring variants are kept: the best on trip.plan, the other two on trip.alternatives, and /choose swaps them. The chooser shows each one's real cost and comfort word; titles come from the variant, blurbs are templated from the days, no model writes them.
- 2026-08-28 — Typed localities resolve to hub cities inside TripRequest (LOCALITIES), and the typed names are kept in `places` for the title. Sending "Srirangapatna" as a city produced a "nothing open to visit" verdict.
- 2026-08-28 — `day_one_start` and `day_end` are real planner inputs, because the form asks "When can you leave?" and "Day should end by" and a promise the planner does not act on is not a promise. The other form answers travel as `preferences` and are stored, not acted on, and the request says so.
- 2026-08-28 — One seeded account; the session cookie is an HMAC of its email under DEMO_PASSWORD. Sign-in parses the urlencoded body with parse_qs rather than adding python-multipart for a single form.
- 2026-08-28 — No LLM runs while a plan is built. The interstitial's sixth stage reads "templates · no AI in this part" rather than the mockup's "the only step that uses AI", because the latter would not be true; the AI speaks in chat and Katha.
- 2026-08-28 — A day named in a chat message beats the model's day_index. In the walk-through the classifier put "add one more food stop to day 2" on day 1.
- 2026-08-28 — "One more food stop" names a kind of place, not a place. Category words map to poi.category and the best unused place of that kind wins, preferring one that serves lunch, because a breakfast-only place added into an afternoon is dropped again by the validator (seen once, and the plan turned tight).
- 2026-08-28 — A Katha built from the same paragraphs, in the same order and language, as a warm_tts.py demo takes the demo's narration and cached WAV. The audio reply carries X-Voice cached|sarvam so the player can say which it was.
- 2026-08-28 — narrate_plan and narrate_katha moved to google/gemini-3.1-flash-lite (Rohan's pick after the bake-off); the id was checked against the live OpenRouter /models list. classify stays on deepseek/deepseek-chat, the model check_env verifies. warm_tts re-run: 14 of 14 segments passed the fact-check.
- 2026-08-28 — The mockup's CSS is copied verbatim; the only overrides are its sticky offsets (42px/60px), which allowed for its own screen switcher, and they sit at the bottom of ty.css with that note. No new colour, no new font.
- 2026-08-28 — Day-map pins closer than 30px are nudged apart so their numbers stay legible; a stop 400 m from the next moves a few pixels. The map is schematic: contour lines are texture, and no river is drawn, because a river is a claim.
